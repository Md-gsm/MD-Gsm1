# راهبرد شاخه‌ها و پشتیبان‌گیری MD-Gsm1

**وضعیت از 2026-10-30 — مسیر موقت تا فعال‌شدن حفاظت واقعی main**

## قواعد کاری

1. شاخه `main` خط پایه تأییدشده است و تا زمان فعال‌شدن حفاظت remote و تکمیل مجوزهای لازم، مستقیماً تغییر نمی‌کند.
2. هر تغییر در شاخه کاری مستقل انجام می‌شود؛ هیچ توسعه مستقیمی روی `main` انجام نمی‌دهیم.
3. PRهای مرحله‌ای تا زمان آماده‌شدن زیرساخت SCM به شاخه کاری Stage 0 متصل می‌شوند، نه به `main`.
4. CI سبز اجازه ادغام به `main` یا شروع G1 را به‌تنهایی صادر نمی‌کند.
5. در این دوره، ادغام PR فرزند فقط در شاخه کاری Stage 0 مجاز است؛ ادغام PR شماره 1 به `main` متوقف می‌ماند.

## پشتیبان مستقل خارج از GitHub

شاخه‌های backup در همان مخزن GitHub هستند؛ بنابراین در برابر حذف یا آسیب کل مخزن، پشتیبان مستقل محسوب نمی‌شوند. پس از نقاط عطف مهم، یک Git Bundle در دیسک یا فضای ذخیره‌سازی جدا از GitHub نیز ساخته و بررسی شود:

```powershell
git fetch origin --prune
$bundle = "..\MD-Gsm1-2026-10-30.bundle"
git bundle create $bundle --all
git bundle verify $bundle
Get-FileHash $bundle -Algorithm SHA256
```

فایل Bundle فقط زمانی بکاپ مستقل تأییدشده محسوب می‌شود که واقعاً ساخته، با موفقیت verify و در محل جداگانه نگهداری شده باشد. وجود branch یا PR به‌تنهایی این شرط را برآورده نمی‌کند.

## شرط خروج از این روش موقت

پس از دسترسی به قابلیت‌های لازم GitHub و تنظیم Required Status Checks روی `main`:
- نام checkهای الزامی از workflow خوانده و روی remote ثبت شود؛
- یک PR آزمایشی با check عمداً شکست‌خورده ساخته شود؛
- مسدودشدن Merge در GitHub عملاً مشاهده و مستند شود؛
- مالک اصلی و جایگزین jobهای CI و تأییدهای سیاست داده موقت و قرارداد ادغام ثبت شوند.

تا آن زمان، وضعیت حفاظت واقعی شاخه در manifest باید false بماند و `g1Authorized` نباید true شود.

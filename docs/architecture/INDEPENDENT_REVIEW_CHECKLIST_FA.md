## B. بازبینی امنیت و حریم خصوصی — مالک پروژه

مسئول امنیت/حریم خصوصی فقط مالک پروژه است. این بررسی باید توسط خود مالک پروژه انجام و نتیجه‌اش ثبت شود:

- تأیید نبود credentials، token، connection string یا دادهٔ محرمانه در مخزن عمومی.
- تأیید سیاست دادهٔ موقت، حداقل‌سازی PII، TTL، حداکثر عمر، محدودیت renewal، purge و alerting.
- بررسی دسترسی loopback-only و نشان اجباری دیتابیس disposable در ابزارهای آزمایشی.
- تأیید اینکه API startup هرگز migration را خودکار اجرا نمی‌کند و ابزار migrator به‌صورت پیش‌فرض دیتابیس بدون نشان آزمایشی را رد می‌کند.
- بررسی عدم ثبت payload، شماره تماس، شناسه قانونی یا raw token در log/artifact.
- ثبت risk/exceptionهای پذیرفته‌شده و اقدام‌های لازم پیش از G1.

پرکردن این سند فقط بعد از انجام واقعی بازبینی مجاز است. CI سبز، پذیرش قبلی یک سیاست، یا وجود این template به‌تنهایی به معنی انجام بازبینی نهایی نیست. پس از تکمیل دو بازبینی، ارجاع این سند و SHA دقیق در `docs/persons/g1-entry-evidence.json` ثبت می‌شود.

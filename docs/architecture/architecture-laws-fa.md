# قوانین بنیادین معماری MD-Gsm

**وضعیت:** مصوب برای طراحی؛ پیش از آغاز ماژول‌های تجاری باید رعایت شود.

این قوانین به همهٔ ماژول‌ها، صفحه‌ها، گزارش‌ها، APIها، مدل‌ها و تغییرات دیتابیس اعمال می‌شوند.

1. **پاکی منبع:** MD-Gsm پروژه‌ای مستقل است. هیچ کد، فایل، اسکریپت، migration، schema، نام‌گذاری داخلی، باینری، وابستگی یا ساختار پیاده‌سازی از پروژهٔ قبلی وارد این مخزن نمی‌شود. تصاویر و فایل HTML فقط مرجع بصری/نام‌گذاری هستند؛ کد آن‌ها کپی نمی‌شود.
2. **یک مالک برای هر مفهوم مشترک:** پیش از افزودن هر مدل، جدول، API یا رفتار، باید مالک دامنه‌ای آن در `data-ownership.md` مشخص شود. هر مفهوم یک مرجع حقیقت دارد.
3. **عدم مسیر موازی:** یک مفهوم مشترک را به دلیل سهولت یک ماژول، با مدل، جدول، موتور محاسبه یا مسیر ثبت دوم پیاده نمی‌کنیم. تغییر مدل مشترک فقط با تصمیم معماری و مهاجرت کنترل‌شده مجاز است.
4. **مرزبندی ماژول‌ها:** ماژول‌ها از قراردادهای عمومی و جهت وابستگی مصوب استفاده می‌کنند؛ دور وابستگی ممنوع است.
5. **یک دیتابیس عملیاتی مرکزی:** داده‌های عملیاتی و مالی در یک دیتابیس مرکزی نگهداری می‌شوند. سال مالی یک دورهٔ حسابداری است، نه دیتابیس سالانه.
6. **حسابداری و موجودی قابل‌ردیابی:** آثار مالی و گردش موجودی از سرویس‌های مالک خود عبور می‌کنند. حذف بی‌ردپای سند قطعی مجاز نیست؛ اصلاح از مسیر سند/رویداد اصلاحی و audit انجام می‌شود.
7. **مجوز در سمت سرور:** مخفی‌بودن منو یا ابزارک امنیت محسوب نمی‌شود. API و سرویس باید مجوز عملیات و دامنهٔ داده را مستقل بررسی کنند.
8. **داشبورد منبع حقیقت نیست:** ابزارک‌ها فقط دادهٔ ماژول مالک را نمایش می‌دهند. دادهٔ نمایشی موقت نباید به‌عنوان دادهٔ واقعی یا ماندهٔ عملیاتی ذخیره شود.
9. **مهاجرت‌های تغییرناپذیر:** migration اعمال‌شده بازنویسی نمی‌شود؛ تغییر بعدی با migration جدید، دلیل مستند، آزمون روی دیتابیس disposable تازه و بررسی سازگاری انجام می‌شود.
10. **پذیرش کامل، نه صرفاً build:** موفقیت build به معنی تکمیل ماژول نیست. هر ماژول علاوه بر build، به آزمون رفتاری، قرارداد، schema، امنیت، یکپارچگی و معیار پذیرش نیاز دارد.
11. **قابلیت‌های نمایش‌داده‌شده ولی پیاده‌نشده:** مقصدهای منو می‌توانند از ابتدا در پوسته حاضر باشند، اما وضعیت «در دست طراحی/پیاده‌سازی نشده» باید روشن باشد و هیچ عملکرد جعلی نمایش داده نشود.

هر استثنا نیازمند تصمیم ثبت‌شده، مالک مشخص، علت، خطرها و آزمون است؛ قانون‌ها با تغییر نام یا ساختار پوشه دور زده نمی‌شوند.

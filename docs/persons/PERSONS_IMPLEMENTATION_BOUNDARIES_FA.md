# وضعیت پیاده‌سازی ماژول اشخاص — مرزهای اجرایی

## محدودهٔ فرم مرجع
فرم ثبت شخص بر اساس تصویر مرجع شامل نوع رابطهٔ «مشتری» یا «همکار» و نوع هویت «حقیقی» یا «حقوقی» است. شرکت نوع هویت حقوقی است، نه نقش تجاری. یک شخص می‌تواند هم‌زمان مشتری و همکار باشد.

## داده‌های هویتی و تماس
- حقیقی: نام، نام خانوادگی و شناسه ملی اختیاری.
- حقوقی: نام قانونی، شناسه ملی حقوقی، کد اقتصادی و نام مسئول.
- موبایل اختیاری است؛ در صورت ارائه باید معتبر و نرمال‌شده باشد. موبایل جایگزین، تلفن ثابت و ایمیل نیز اختیاری‌اند.
- شماره‌های فارسی و عربی در ورودی به رقم لاتین تبدیل می‌شوند؛ موبایل ایران به قالب +98 نرمال می‌شود.
- آدرس شامل کشور، استان، شهر، کد پستی و نشانی کامل است. کشور پیش‌فرض IR است.
- سقف اعتبار متعلق به Finance/Accounts Receivable، تخفیف و قواعد قیمت متعلق به Pricing، و روش/ابزار پرداخت متعلق به Treasury است؛ این داده‌ها نباید از قرارداد Persons منتشر یا مبنای عملیات قرار گیرند.
- PAN کامل در هیچ ماژولی نباید ذخیره شود.
- تنظیمات پیامک تعمیر، آماده تحویل و تبلیغات جداگانه‌اند. پیامک تبلیغاتی به‌صورت پیش‌فرض خاموش است.
- یادداشت داخلی حداکثر ۲۰۰۰ نویسه است و نباید در جست‌وجوی عمومی یا لاگ‌ها ظاهر شود.

## چندکاربره و چندسیستمی
داده‌ها در PostgreSQL مرکزی قرار می‌گیرند و کلاینت‌ها نباید مستقیماً به پایگاه داده متصل شوند. actorId برای ثبت ممیزی از هویت احراز‌شدهٔ سمت سرور گرفته می‌شود؛ هرگز از بدنهٔ درخواست پذیرفته نمی‌شود.

## موانع فعال‌سازی API و UI
ADR-0006 استفاده از توکن opaque را الزام کرده و اجرای IdentityAccess را تا بازبینی امنیتی و مجوز صریح G1 مسدود می‌کند. در وضعیت فعلی g1Authorized=false است؛ بنابراین endpoint عملیاتی و فرم ذخیره‌ساز شبکه‌ای نباید بدون اعتبارسنجی سمت سرور و کنترل وضعیت لغو نشست فعال شوند. API و UI عملیاتی تا تکمیل این پیش‌نیازها مسدود هستند.

## ملاحظات Migration
Migration 0002 فقط schema اشخاص را ایجاد می‌کند و در Startup اجرا نمی‌شود. اجرای آن همچنان تابع marker دیتابیس آزمایشی و فرمان صریح DbMigrator است. Migration روی دیتابیس واقعی/تولیدی اجرا نشده است.

# وضعیت پیاده‌سازی ماژول اشخاص — مرزهای اجرایی

## محدودهٔ فرم مرجع
فرم ثبت شخص بر اساس تصویر مرجع شامل نوع رابطهٔ «مشتری» یا «همکار» و نوع هویت «حقیقی» یا «حقوقی» است. شرکت نوع هویت حقوقی است، نه نقش تجاری. یک شخص می‌تواند هم‌زمان مشتری و همکار باشد.

## داده‌های هویتی و تماس
- حقیقی: نام، نام خانوادگی و شناسه ملی اختیاری.
- حقوقی: نام قانونی، شناسه ملی حقوقی، کد اقتصادی و نام مسئول.
- موبایل اصلی در قرارداد فعلی اختیاری است؛ موبایل جایگزین، تلفن ثابت و ایمیل نیز اختیاری‌اند. قواعد نرمال‌سازی شماره ایران همچنان طبق ADR-0004 اعمال می‌شود.
- شماره‌های فارسی و عربی در ورودی به رقم لاتین تبدیل می‌شوند؛ موبایل ایران به قالب +98 نرمال می‌شود.
- آدرس شامل کشور، استان، شهر، کد پستی و نشانی کامل است. کشور پیش‌فرض IR است.
- اعتبار به ریال صحیح ذخیره می‌شود؛ تخفیف بین صفر تا صد درصد است.
- برای کارت بانکی فقط چهار رقم آخر مجاز است؛ PAN کامل نباید ذخیره شود.
- تنظیمات پیامک تعمیر، آماده تحویل و تبلیغات جداگانه‌اند. پیامک تبلیغاتی به‌صورت پیش‌فرض خاموش است.
- یادداشت داخلی حداکثر ۲۰۰۰ نویسه است و نباید در جست‌وجوی عمومی یا لاگ‌ها ظاهر شود.

## چندکاربره و چندسیستمی
داده‌ها در PostgreSQL مرکزی قرار می‌گیرند و کلاینت‌ها نباید مستقیماً به پایگاه داده متصل شوند. actorId برای ثبت ممیزی از هویت احراز‌شدهٔ سمت سرور گرفته می‌شود؛ هرگز از بدنهٔ درخواست پذیرفته نمی‌شود.

## وضعیت واقعی API، Runtime و UI در main

- endpoint محافظت‌شده `GET /api/v1/persons/{partyId}` برای جزئیات شخص پیاده‌سازی شده است. هویت actor از مرز نشست IdentityAccess که در PostgreSQL اعتبارسنجی می‌شود به دست می‌آید؛ فیلدهای حساس به مجوز زنده `persons.sensitive.read` نیاز دارند.
- APIهای ایجاد و جست‌وجوی شخص و چرخه کامل Contact Point هنوز کامل نیستند.
- Runtime امنیت/نشست IdentityAccess در سمت سرور وجود دارد. مسیرهای HTTP ورود و تغییر رمز پیاده‌سازی و در تست API به‌همراه PostgreSQL موقت پوشش داده شده‌اند؛ ورود HTTP با تنظیم `IdentityAccess:HttpLoginEnabled` کنترل می‌شود و مقدار پیش‌فرض آن خاموش است. این وضعیت مجوز استقرار تولیدی یا فعال‌سازی G1 نیست.
- UI پیش‌نمایش فعلی هنوز داده ساختگی دارد و فرم عملیاتی ثبت/ویرایش متصل به API محسوب نمی‌شود.
- `g1Authorized=false` باقی می‌ماند؛ اجرای عملیات نوشتن عملیاتی، استقرار احراز هویت تولیدی و فعال‌سازی ماژول به عبور از گیت‌های مستقل و مجوز صریح مالک نیاز دارد.

## ملاحظات Migration
Migration کسب‌وکاری اشخاص در مخزن وجود دارد و در مسیر application-owned `tools/MDGsm.DbMigrator` ثبت شده است. اجرای آن در CI فقط روی دیتابیس‌های disposable PostgreSQL 18 (Linux/Windows) اعتبارسنجی شده است. Migration در Startup به‌صورت خودکار اجرا نمی‌شود و روی دیتابیس واقعی/تولیدی اعمال نشده است. اجرای آن فقط از مسیر صریح و کنترل‌شده DbMigrator و پس از مجوز مستقل مجاز خواهد بود.

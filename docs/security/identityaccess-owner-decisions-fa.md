# تصمیم‌های مالک محصول برای IdentityAccess
تاریخ: 2026-11-04 | وضعیت: تصمیم‌های محصول ثبت‌شده؛ جزئیات فنی پیشنهادی نیازمند تست و بازبینی امنیتی.

## مرز و مالکیت
IdentityAccess مالک حساب، اعتبارنامه، قفل ورود، نشست، نقش، مجوز و رویداد امنیتی است. Desktop غیرقابل‌اعتماد، API مرز enforcement و PostgreSQL منبع حقیقت است. کلاینت‌ها اتصال مستقیم DB ندارند؛ ثبت‌نام عمومی ممنوع است.

## شناسه ورود
- ورود فقط با نام کاربری و رمز عبور است.
- نام کاربری می‌تواند فقط عدد، فقط حرف یا ترکیبی از حروف و اعداد باشد.
- ایمیل و موبایل فقط اطلاعات تماس/بازیابی‌اند و شناسه ورود نیستند.
- پیشنهاد فنی برای پشتیبانی حروف فارسی و لاتین: Unicode NFC، پذیرش Unicode Letter و Decimal Digit، طول 3..64، عدم پذیرش فاصله/نشانه‌گذاری/کنترل‌کاراکتر؛ کلید یکتا از مقدار canonical با case normalization برای لاتین. حروف فارسی/عربی متفاوت خودکار یکی نشوند. این قواعد باید با تست collision و سازگاری تأیید شوند.

## رمز و بازیابی
- کاربر رمز خودش را با واردکردن رمز فعلی و دو بار رمز جدید تغییر می‌دهد.
- فقط مدیر مجاز می‌تواند رمز کاربر دیگری را در صورت فراموشی reset کند؛ مدیر رمز قبلی را نمی‌بیند.
- reset مدیریتی، تغییر اجباری در ورود بعدی را فعال می‌کند.
- تغییر رمز خود کاربر و reset مدیر هر دو credential_version را افزایش داده و تمام نشست‌های آن حساب را باطل می‌کنند؛ ورود مجدد لازم است.
- رمز فقط با password hasher پشتیبانی‌شده و نسخه‌دار ذخیره می‌شود؛ plaintext، رمز قابل‌بازیابی و crypto سفارشی ممنوع.
- بازیابی مدیر کل با تأیید ایمیل و موبایل؛ کدهای اضطراری یک‌بارمصرف و آفلاین. هیچ backdoor یا رمز ثابت بازیابی وجود ندارد.

## مدیر اولیه
- حساب آغازین username=admin و bootstrap password=admin است.
- این اعتبارنامه فقط در راه‌اندازی یک‌باره محلی روی سرور پذیرفته می‌شود. تا تغییر رمز و تکمیل پروفایل مدیر، listener شبکه‌ای و عملیات عادی/تجاری غیرفعال می‌مانند (fail-closed).
- اولین ورود فقط به جریان اجباری تغییر رمز و تکمیل/تغییر نام کاربری و مشخصات مدیر می‌رود.
- bootstrap اتمیک، audit‌شده و غیرقابل تکرار است. قطع عملیات نباید حساب نیمه‌راه یا listener شبکه‌ای باز بسازد.
- مقدار خام admin/admin هرگز در source، installer، config، migration، log یا telemetry تعبیه/ثبت نمی‌شود؛ فقط در ورودی امن setup دریافت و hash می‌شود. seed ثابت رمز ممنوع است.

## نشست و هم‌زمانی
- نشست از دید محصول تا زمانی معتبر است که برنامه کاربر باز باشد؛ خروج صریح، نشست را revoke می‌کند.
- سقف هم‌زمانی از پنل مدیریت قابل تنظیم است؛ مقدار آغازین پیشنهادی 5 کاربر فعال، نه ثابت در کد.
- سقف برای تعداد حساب‌های متمایز فعال است؛ چند نشست از یک حساب یک کاربر فعال محسوب می‌شود. سقف ثابت per-account وجود ندارد.
- برای تشخیص بسته‌شدن ناگهانی، heartbeat/lease لازم است. پیشنهاد اولیه: heartbeat=30s و lease=180s؛ قطع کوتاه شبکه فوراً نشست را نمی‌بندد.
- اگر سقف پر باشد ورود حساب جدید رد می‌شود و نشست‌های موجود اخراج نمی‌شوند. کاهش سقف پایین‌تر از active count فقط ورودهای بعدی را متوقف می‌کند.
- وضعیت نشست فقط در PostgreSQL authoritative است؛ cache محلی اعتبار نشست ممنوع.

## قفل و rate limit
- 5 تلاش ناموفق در پنجره 15 دقیقه‌ای، قفل 15 دقیقه‌ای حساب را ایجاد می‌کند.
- ورود موفق شمارنده را پاک می‌کند؛ پس از پایان قفل، پنجره تلاش جدید آغاز می‌شود.
- rate limit مستقل بر اساس مبدأ درخواست نیز لازم است تا حمله از یک مبدأ به حساب‌های متعدد مهار شود.
- پاسخ برای حساب ناشناخته، رمز غلط، حساب غیرفعال و قفل‌شده عمومی و یکسان است.
- فقط داده حداقلی مبدأ ثبت شود؛ نگهداری IP خام نیازمند سیاست جداگانه است.

## نقش‌ها
نقش‌ها در catalog تعریف می‌شوند ولی به‌ازای نقش‌ها حساب کاربری ساخته نمی‌شود. یک حساب می‌تواند چند نقش داشته باشد. فقط حساب bootstrap پس از تکمیل setup، super_admin می‌گیرد.

| role key | عنوان | محدوده اولیه |
|---|---|---|
| super_admin | مدیر سیستم | مدیریت حساب‌ها، نقش/مجوز، تنظیمات پایه، bootstrap و recovery |
| manager | مدیر/صاحب‌کار | مدیریت روزمره؛ بدون حذف/ساخت مدیر سیستم، تنظیمات پایه و عملیات انحصاری super_admin |
| receptionist | پذیرش‌گر | اشخاص، پذیرش، تحویل، ارتباط مشتری؛ بدون مالی حساس/حذف سند/تنظیمات |
| technician | تکنسین | پذیرش تخصیص‌یافته، شرح تعمیر، قطعه مصرفی، زمان؛ بدون قیمت نهایی/فاکتور |
| warehouse | انباردار | رسید، حواله، انبارگردانی، کاردکس؛ مالی محدود |
| salesperson | فروشنده | فروش، مشاهده موجودی و آخرین قیمت فروش |
| purchaser | کارپرداز/خریدار | خرید و رسید انبار |
| cashier | صندوق‌دار | دریافت، پرداخت و صندوق |
| accountant | حسابدار | اسناد مالی، سودوزیان، تراز، دفترکل و بستن دوره طبق مجوز |
| viewer | مشاهده‌گر | فقط مشاهده و گزارش |

مجوزها مستقل و granular هستند؛ deny-by-default. مجوزهای حساس مستقل: حذف سند، تغییر قیمت ثبت‌شده، بستن دوره، مدیریت کاربران، تغییر نقش/مجوز، تنظیمات پایه و بازیابی اضطراری. تکنسین فقط رکوردهای تخصیص‌یافته را در سمت API می‌بیند. manager مجوزهای روزمره گسترده دارد اما super_admin را نمی‌سازد/حذف یا تنزل نمی‌دهد و تنظیمات امنیتی پایه را تغییر نمی‌دهد.

## ممیزی و نگهداری
ممیزی: ورود/خروج، تلاش ناموفق/قفل، تغییر/reset رمز، تغییر نقش/مجوز، revoke نشست، تغییر سقف هم‌زمانی، bootstrap و recovery. هیچ رمز، hash رمز، raw token، recovery code یا secret در log/audit ثبت نمی‌شود.
مدت نگهداری هنوز تصویب نشده است. پیشنهاد قبلی 24 ماه برای رخدادهای حساس و 12 ماه برای تلاش ناموفق/revoke صرفاً پیشنهاد است و الزام قانونی/استاندارد جهانی تلقی نمی‌شود؛ نیازمند تصویب و بررسی حقوقی است.

## تفکیک تصمیم مصوب و پیشنهاد فنی
مصوب مالک: ورود username/password؛ email/mobile صرفاً تماس/بازیابی؛ تغییر رمز توسط خود کاربر؛ reset مدیر؛ اجبار تغییر پس از reset و اولین ورود؛ bootstrap admin/admin؛ قفل 5/15؛ سقف هم‌زمانی قابل تنظیم با مقدار پیشنهادی 5؛ ده نقش فوق؛ چندنقشی؛ عدم ثبت‌نام عمومی.
پیشنهادی و نیازمند تست/بازبینی: قواعد NFC و کاراکتر username؛ heartbeat/lease؛ شمارش حساب‌های متمایز؛ جزئیات rate-limit مبدأ؛ permission matrix نهایی؛ retention؛ جزئیات recovery codes و bootstrap.

## عدم مجوز فعال‌سازی
این سند مجوز runtime نیست. تا بازبینی امنیتی/معماری و مجوز رسمی G1، `g1Authorized=false`؛ بدون endpoint ورود، migration عملیاتی، listener شبکه، اتصال Persons یا تغییر production.

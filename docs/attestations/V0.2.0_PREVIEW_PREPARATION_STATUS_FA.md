# وضعیت آماده‌سازی پیش‌نمایش ماژول اشخاص — v0.2.0

تاریخ ثبت: 2026-10-28

## تغییرات موجود در بسته

- صفحه نمایشی فارسی و راست‌به‌چپ برای «اشخاص» به `MainWindow.xaml` و code-behind اضافه شده است.
- مسیر منوی `BASE-P-06` و دکمه داشبورد به صفحه پیش‌نمایش وصل‌اند.
- چهار ردیف نمایشی کاملاً ساختگی، جست‌وجو و فرم افزودن حافظه‌ای وجود دارد.
- متن رابط صریح می‌گوید افزودن در پایگاه داده ذخیره نمی‌شود.
- اسکریپت Publish خودبسنده win-x64 و قالب Inno Setup اضافه شده است.
- Workflow جداگانه برای تولید artifact نصب‌کننده در Windows CI اضافه شده است.
- G1 همچنان مسدود است و هیچ Persons API، جدول تجاری یا Migration اضافه نشده است.

## شواهد قابل اجرا در محیط آماده‌سازی فعلی

- Python static gates: PASS؛ همه gateها PASS یا PASS-N/A مطابق وضعیت نبود runtime ماژول‌اند.
- سیاست fail-closed: 10 آزمون PASS.
- تمام فایل‌های XAML، csproj و props با parser XML خوانده شدند.
- همه JSONها معتبرند.
- 13 نام event handler در XAML کشف شد؛ handler مفقود وجود نداشت.
- آزمون ثابت‌بودن مرزهای API/DB برای فرم نمونه در تست .NET اضافه شده است، اما خود مجموعه تست نسخه v0.2.0 در این محیط اجرا نشده است.

## محدودیت‌های مهم

- این محیط ابزار `dotnet`، Windows، PowerShell و Inno Setup ندارد؛ بنابراین Build ویندوزی، تست‌های .NET پس از تغییر UI، Publish و تولید واقعی فایل Setup EXE هنوز اجرا/تأیید نشده‌اند.
- فایل `.iss` و `Build-Windows-Installer.ps1` ابزار ساخت نصب‌کننده‌اند؛ آن‌ها خودشان فایل EXE نصب‌کننده نیستند. فایل نصب‌کننده باید با اجرای اسکریپت روی Windows دارای .NET 10 SDK و Inno Setup 6 تولید شود.
- برنامه نصب‌شده به Python نیاز ندارد؛ Python صرفاً برای بخشی از کنترل‌های ایستای توسعه/CI استفاده می‌شود.
- صفحه اشخاص یک پیش‌نمایش تعاملی صرفاً حافظه‌ای است؛ نباید با ماژول عملیاتی یا نگهداری پایدار داده اشتباه گرفته شود.
- Remote branch protection هنوز تأیید نشده است؛ G1 همچنان غیرمجاز است.

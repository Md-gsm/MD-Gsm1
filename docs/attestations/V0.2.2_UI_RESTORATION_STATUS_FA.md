# گزارش وضعیت v0.2.2 — اصلاح هدر/منوها و وفاداری بیشتر به HTML مرجع

تاریخ: 2026-10-28

## رفتار رابط که در سورس تغییر کرده است

- ساختار هدر به ترتیب مرجع بازچینی شد: نوار منو در ردیف اول، برند و اقدامات سریع در ردیف دوم، پنل dropdown تمام‌عرض در ردیف سوم.
- پنل dropdown زیر برند/اقدامات سریع قرار می‌گیرد و وقتی نمایش داده می‌شود، هدر گسترش پیدا می‌کند؛ منو به‌صورت Workspace/Tab ساخته نمی‌شود.
- ریشه‌های منو فقط با `MouseEnter` باز می‌شوند. `Click` روی ریشه منو toggle انجام نمی‌دهد. حرکت موس در محدوده کل هدر dropdown را حفظ می‌کند؛ خروج از هدر و `Escape` آن را می‌بندد.
- عنوان غیرمرجع بالای داشبورد حذف شد؛ نوار برند/مرکزسازی اضافه حذف شد؛ داشبورد شامل KPI، تب و جدول پذیرش، نمودار چندسری، بار کاری تکنسین‌ها، دو نمودار ستونی عمودی ۱۰تایی، انتخاب دوره ماهانه/سالانه و فوتر تیره است. دکمه تشخیصی API از فوتر حذف شد؛ پیش‌نمایش برای نمایش رابط به API نیاز ندارد.
- داده‌های داشبورد صرفاً ساختگی‌اند. پیش‌نمایش اشخاص همچنان حافظه‌ای است و هیچ API تجاری/جدول اشخاص/Migration ندارد.
- HTML مرجع صرفاً برای راهنمایی بصری استفاده شده است؛ فایل HTML یا اسکریپت اجرایی آن به WPF اضافه نشده است.

## بررسی انجام‌شده در این محیط

- XML parse برای `MainWindow.xaml` و فایل‌های پروژه: PASS.
- همه event handlerهای ثبت‌شده در XAML متد هم‌نام در code-behind دارند: PASS.
- ریشه منو فقط با `MouseEnter` فعال است؛ کلیک-toggle و `DestinationView` وجود ندارند: PASS.
- گیت‌های Python معماری/سیاست: همه گیت‌های قابل‌اجرا PASS و موارد runtime اجرا‌نشده به شکل صریح PASS-N/A.
- آزمون‌های سیاست: ۱۰ موفق، صفر شکست.

## محدودیت‌های مهم

این محیط ابزار `dotnet`، Windows WPF و Inno Setup ندارد؛ بنابراین نمی‌توان در اینجا ادعای Build واقعی WPF، اجرای تست‌های .NET یا تولید/آزمون Setup.exe کرد. روی Windows باید `dotnet build` و `dotnet test` اجرا شود و برای ساخت نصب‌کننده، `scripts\Build-Windows-Installer.ps1` اجرا گردد. نصب‌کننده نهایی هنوز در این محیط تولید نشده است.

خروجی مورد انتظار ساخت Windows: `artifacts\installer\MD-Gsm-Persons-Preview-Setup-v0.2.2.exe`.

# گزارش وضعیت نسخه v0.2.4 — داشبورد تمام‌عرض و منوهای مطابق تصاویر مرجع

تاریخ: ۲۸ اکتبر ۲۰۲۶
شاخه: `fix/fullscreen-dashboard-worklist-v0.2.4`
پایه: `MD-Gsm_Phase1_CleanFoundation_Stage9_CSharpShell_MenuNavigation`؛ Stage10 استفاده نشده است.

## تغییرات سورس

- پنجره در XAML به حالت `Maximized` تنظیم شده و در رویداد `MainWindow_Loaded` دوباره اطمینان حاصل می‌شود که پنجره روی فضای نمایشگر فعلی حداکثر باشد. حداقل عرض ۹۰۰ پیکسل است؛ داشبورد عرض ثابت ندارد.
- محتوا با `HorizontalAlignment=Stretch` کل عرض پنجره را مصرف می‌کند. در صفحه‌های کوتاه، پیمایش عمودی حفظ می‌شود و ارتفاع فهرست تعمیرات از viewport در بازه ۲۱۵ تا ۳۶۰ پیکسل مشتق می‌شود.
- فهرست تعمیرات پنج تب دارد: `deliveryToday`, `intakeToday`, `tech`, `partner`, `all`. تب‌های اول و دوم «تحویل امروز» و «ورودی امروز» هستند؛ تعدادها از همان ۱۲ رکورد ساختگی محاسبه می‌شوند.
- دو نمودار ده‌دسته‌ای با `UniformGrid Columns="10"` عرض خود را تقسیم می‌کنند.

## بازسازی ساختار منو از تصاویر پارسیان

- ۱۱ منوی ریشه به ترتیب تصاویر حفظ شدند.
- کاتالوگ `menu-catalog-fa.json` به ۱۸۷ گزینه و ۱۲ اقدام سریع مرتب شده؛ CSV و Markdown متناظر از همین داده تولید شده‌اند.
- هر گروه حالت نمایش صریح دارد: `direct`، `submenu` یا `hidden`. تصمیم زیرمنو دیگر بر اساس استثنای عنوان «رسیدها» یا نمایش اشتباه هر گروه به‌عنوان فلای‌اوت انجام نمی‌شود.
- فاکتورها، گزینه‌های مستقیم حسابداری و حقوق، جست‌وجو/راس‌گیری چک، آیتم‌های اطلاعات پایه و ابزارها مستقیماً در منوی ریشه ظاهر می‌شوند؛ زیرمنو فقط برای گروه‌هایی است که تصویر واقعاً پیکان/فلای‌اوت نشان می‌دهد.
- جداکننده‌ها در سطح گروه و گزینه تعریف شده‌اند. میانبرهای صفحه‌کلید از metadata همان گزینه می‌آیند؛ shortcutهای قدیمی که به گزارش چک اشتباهاً نسبت داده شده بودند حذف شدند.
- گزینه مفقود «لیست چک‌های دریافتی عودت‌شده» مطابق اسکرین‌شات 185552 اضافه شد؛ میانبرهای مشاهده‌شده Ctrl+W، Shift+P، Ctrl+F13 و Ctrl+C نیز دقیق شدند. عنوان «حوزه‌های مالیاتی» و «موجودی کالا در سطح‌ها» اصلاح و جداکننده‌های اطلاعات پایه تکمیل شدند. سه گزینه مستقیم جست‌وجو، راس‌گیری و راس‌گیری هوشمند چک با اسکرین‌شات 185526 هم‌تراز هستند.
- برای `سامانه اقساط`، `چک‌های تضمینی` و `تولید` فقط وجود ردیف زیرمنو اثبات شده است؛ محتوای بازنشده حدس زده نشده است. برای `سامانه‌های مالیاتی` و `راهنما` نیز عنوان ریشه دیده می‌شود، اما فهرست داخلی در تصاویر باز نشده؛ در نتیجه ریشه حفظ شده اما popup ساختگی نمایش داده نمی‌شود.
- گزینه‌هایی که از HTML یا پیشنهادهای توسعه به‌دست آمده‌اند ولی در تصاویر منبع دیده نشده‌اند جداگانه برچسب خورده‌اند؛ گزینه‌های آینده به حالت `hidden` درآمده‌اند. `BASE-P-06` تنها مورد اختصاصی MD-Gsm است که برای پیش‌نمایش اشخاص در UI قابل مشاهده می‌ماند.

## کنترل‌های اجراشده در این محیط

- بررسی ایستا باید فایل JSON را parse کند و یکتایی IDها، ۱۱ عنوان منوی اصلی، حالت نمایش گروه‌ها، جداکننده‌ها، میانبرها و وجود ورودی‌های کلیدی را بررسی کند.
- آزمون‌های سیاستی موجود برای قفل‌های اشخاص مستقل از این تغییر UI هستند.
- Build واقعی WPF، آزمون‌های .NET و مشاهده تصویری runtime روی ویندوز در این محیط انجام نشده‌اند؛ ادعای قبولی آن‌ها مطرح نیست. این موارد باید روی Windows با .NET 10 SDK و سپس در اجرای واقعی برنامه بررسی شوند.

## مرز معماری

این تغییرها صرفاً رابط و کاتالوگ ناوبری‌اند. تمام داده‌های داشبورد ساختگی هستند؛ API عملیاتی اشخاص، جدول تجاری، Migration یا ذخیره‌سازی دائمی اضافه نشده است. `g1Authorized=false` باقی می‌ماند.

دستورات بررسی در ویندوز:

```powershell
.\scripts\Run-Persons-Preview.ps1 -Build
```

و برای آزمون/ساخت نصب‌کننده:

```powershell
.\scripts\Build-Windows-Installer.ps1
```
